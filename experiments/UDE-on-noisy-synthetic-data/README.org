* Noisy synthetic UDE studies
Start with the question. Paths in the table are relative to the named study.

| Study | Question | Fit driver in runs/ | Fit records under Results/ |
|-------+----------+---------------------+---------------------------|
| Ablating-on-replicates | What changes with additional replicates? | replicate-sweep.jl | sweep/ |
| Fixed-budget-sweep | How should a fixed sampling budget be allocated? | fixed-budget-sweep.jl | sweep/ |
| Ablating-on-regularization | How do regularization and stopping affect recovery? | regularization-sweep.jl | sweep-errmodel-pinned-data/ |

For the first two studies, see =analysis/replicate-sweep-plot.jl= and
=analysis/sweep-plots.jl= respectively. The regularization study has a second
stage: =runs/symreg-sweep.jl= reads the fit records and writes =Results/sr-sweep/=.
Its =analysis/= directory also contains two independent analyses of the fit
records. Neither requires the symbolic-regression stage. From the repo root:

#+begin_src sh
A=experiments/UDE-on-noisy-synthetic-data/Ablating-on-regularization/analysis
julia --project=. "$A/early-stopping-and-recovery.jl"
julia --project=. "$A/regularization-by-sampling-design.jl"
julia --project=. "$A/compose-recovery-and-design.jl"   # optional combined layout
#+end_src

Each question produces a same-named PDF in the study's =figures/= directory;
composition produces =recovery-and-design-preview.pdf=. The first compares
stopping-arm score distributions and shows recovered terms against truth in
four pooled score quartiles (predictions sampled nearest the 81 scoring times).
The second compares median scores across the λ grid by sampling design,
pooling stopping arms and seeds. It does *not* measure best-quartile frequency.
Both use =analysis/fit-population.jl=: successful proportional-error fits at
noise fraction 0.2, scored by the maximum of the three channel relative errors.
The inputs are the saved fit records, not a notebook session or aggregate cache.
The composition script controls layout only; no manuscript figure number is assumed.

* Symbolic recovery: three independent questions
From the repository root, with =A= set as above, run =julia --project=. "$A/<script>.jl"=:

| Script | Unit | Question / output |
|--------+------+-------------------|
| sr-paired-recovery-error | SR run | Main 3A: is the expression closer to truth than its own network on the same predicted states? |
| sr-distillation-error (supplement) | SR run | Does the selected expression approximate the network and truth on the same predicted states? Dashed line: median network-to-truth error. |
| sr-selected-structures | SR run | Which sign-conditioned structural keys are selected most often? Top eight per channel plus the remainder. |
| sr-recovery-regression | fit/channel | Forest plot of categorical main-effect log odds ratios (95% Wald intervals) for finding truth and selecting it among finders. Reference: smallest observed factor level. Stages with fewer than 20 events or non-events are not fitted. |
| sr-search-versus-selection | fit/channel | Was the true structure present on any stored Pareto front, and was it ever selected? Fractions by within-channel network-error decile, with Wilson intervals. |
| compose-sr-recovery | mixed | Combine paired errors, structural frequencies and search vs selection in =figures/sr-recovery-preview.pdf= without rerunning fits or searches. |

Standalone PDFs use the script basename under =figures/=. These are question-driven
views of =tmp/test-sr-3.jl=, not exports of every exploratory cell. A front hit
means a match on a *saved front*, not proof that the search never visited any
other form. A cell-level hit is counted once across successful SR seeds.

=analysis/sr-population.jl= joins successful =Results/sr-sweep/= runs to their
parent =Results/sweep-errmodel-pinned-data/= fits. =Src/SRSkeleton.jl= defines
structural equivalence. The validated =outputs/sweep-cache/= snapshots are
built from the records on first use; existing snapshots do not check source
freshness. After changes to either sweep, run one script with =SR_REFRESH=1=
to rebuild both snapshots before regenerating the remaining figures.

* Running and reading
Start Julia with =julia --project=.= from the repository root. Include a fit
driver to inspect its grid; running it as a script starts fits. For example:
#+begin_src julia
include("experiments/UDE-on-noisy-synthetic-data/Fixed-budget-sweep/runs/fixed-budget-sweep.jl")
sweep_status(CONFIGS, SWEEP_DIR)
#+end_src
Use a fresh session per driver. =Fixed-budget-sweep/sweep.jl= is the older
standalone driver, not the entry point above. Shared noisy sampling, fitting,
and sweep execution live in =common/=. Use =<study>/runs/= for drivers and
=<study>/analysis/= for maintained plotting scripts; the former study-root
aliases are gone. When replaying an old job log, insert =runs/= before the
relocated driver's filename. Do not change its =Results/= path.

Scratch and promoted notebooks both include =common/synthetic-data-gen.jl= or
=common/sweep-runner.jl= directly; there are no experiment-root aliases.

* From scratch to analysis
1. Copy =templates/analysis.jl= to a new file under the repository's =tmp/=.
   Fill in the question, study, and exact input sweep. The setup finds the
   enclosing Julia project; it does not assume a particular notebook depth.
2. Read cached records from =sweep_dir=; don't include a driver to obtain data.
   Write generated PDFs/PNGs to =figures_dir= and named tables or other derived
   data to =summaries_dir=. Record the input configuration/seeds or filters.
3. When the analysis is worth rerunning, move it to =<study>/analysis/= with a
   descriptive name, rerun from a fresh session, and link it here. No existing
   scratch notebooks are part of this migration.

* Result-path migration: deferred
=Results/= (capital R), dated archives, and their existing figures stay where
current consumers expect them. New maintained plots write to =<study>/figures/=;
older scratch plotting scripts retain their original behavior. No sweep data
is copied, renamed, or added to Git as part of the layout change.

If migrating later, first inventory readers (including =tmp/= notebooks) and
back up the untracked archives. Map each existing fit or SR run to a stable
run ID under =results/fit-sweep/= or =results/sr-sweep/=, recording its old
path and configuration. On case-insensitive filesystems do not create
=results/= beside =Results/=. Update readers and the template together, verify
record counts and regenerate a representative figure, then retire old paths.
